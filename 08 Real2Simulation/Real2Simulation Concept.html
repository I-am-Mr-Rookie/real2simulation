Three ways in, one world out

Users don't need to film anything. Every path ends in the same place: a 3D world with an experiment in it, an agent in the sidebar, and real numbers.

01 · UPLOAD

Upload a clip

Any 10–60 s video: your own, or a licensed public clip. A clip of something moving lets the system measure real physics. (Decided Oct 27: the demo uses licensed public clips, not footage filmed for the project.)

02 · LIBRARY

Pick a curated demo

Ready-made worlds, e.g. the Apollo 15 hammer-and-feather drop on the Moon. Open one, run it, change it. These are precomputed, so they're instant and free to view.

03 · ASK

Describe an idea

"I want to see whether a heavier pendulum swings slower." The agent searches the library. If there's a match you open it; if not, it offers to build one from the closest template.

The decision that makes or breaks it

Measuring g in a simulation only returns the g you typed in

If the world is pure simulation, "measure gravity" is circular, and a sharp judge will notice within seconds. The fix is to be explicit about where every number comes from. Three modes do that, and the UI always labels a value as measured from reality or simulated.

Mode A · Measure

Real motion in, real numbers out

The video shows something moving: a dropped ball, a swinging bag. SAM 3.1 tracks it, the 3D rebuild supplies metres and "down", and a fitter computes g, friction or restitution with uncertainty.

clip→track→3D→fit→g ± σ
Chosen · Real2Sim

Reality calibrates the simulation

Values fitted in Mode A become the physics of the 3D world. The agent watches only the first part of a clip, predicts the rest ("lands 1.42 ± 0.04 m away"), then overlays its prediction on the real frames it never saw. This is the demo moment, and it needs no new filming.

fit→world→predict→reveal→compare
Mode C · Virtual lab

A static room becomes a lab

No motion needed. Virtual instruments carry realistic error: human stopwatch reaction time, 30/240 fps cameras, ruler resolution. In Mystery-g, the world's gravity is hidden (Earth? Mars? random?) and the user has to measure it. That makes measuring g meaningful again.

room→apparatus→noisy trials→fit→reveal

The agent proposes, code decides

The model never edits the 3D world directly. It writes an experiment spec (JSON). Deterministic code validates the spec, builds the world, runs it, and computes every number. This is the winning pattern from the Built-with-Opus galleries, and it keeps a demo from breaking live.

Example spec the agent writes

{
  "template": "projectile_off_edge",
  "scene": "my-desk-01",
  "launch": {"surface": "desk_top", "edge": "front",
             "speed_mps": [1.5, 3.0]},
  "gravity": {"source": "fitted", "value": null},
  "instruments": ["stopwatch_human", "camera_240fps",
                  "tape_measure_1mm"],
  "measure": ["g", "launch_speed"],
  "trials": 10
}

What the sidebar agent can do

  • Edit the world: "make the ramp 30°", "swap the ball for a steel bearing". It patches the spec, then validates and rebuilds.
  • Search the library: "a pendulum where the mass changes". Muse Spark ranks matches; the agent opens one or adapts the nearest template.
  • Explain: how the experiment works, why the method measures g, where systematic error comes from. Answers cite the run's own numbers.
  • Write: a LaTeX lab report (aim, apparatus, method, data table, fit, uncertainty, conclusion) exported as PDF.
  • Draw: charts and flowcharts generated from data in code; Muse Image for apparatus illustrations.
  • Custom experiments: anything typed by name is mapped to templates. If none fits, it composes from primitives (bodies, ramps, strings, springs) under an "experimental" badge.

Platforms: big screens first, phones still welcome

Primary

Desktop browser

Windows, macOS, Linux, tablets in landscape. Full workspace: rail, 3D viewport, instruments, sidebar.

Day 7

Installable PWA

The same site with a manifest and service worker. "Install app" on Android Chrome and "Add to Home Screen" on iOS Safari give a full-screen, landscape-locked app with no browser bars. Phones mostly upload clips and view worlds.

After judging

Android APK, iOS app

An APK can wrap the PWA (Trusted Web Activity via Bubblewrap) in about an hour; sideloading is free, and Play Store listing costs $25 once. A native iOS app needs a $99/year Apple account: skip it.

On jitter: wrapping the site in an app doesn't make WebGL faster. A rendering budget does: cap the device pixel ratio, use fewer splats on phones (level of detail), and stop rendering when nothing moves. That's built into the viewer from day 3.

8-day plan with kill-gates

The brain dump holds about a month of work. This plan ships the core loop first and treats everything else as optional. Dates are Asia/Dhaka; deploy to Railway on day 1, not on the last day.

Gates (fail → fallback, never stall)

  • Gate R · Oct 28 Three public indoor clips rebuilt in under 4 min each, floor plane found, known-object sizes (door, A4, ball) within 10%. Fallback 1: single keyframe with SAM 3D Objects plus "how tall is the desk?". Fallback 2: simple boxes and planes textured with video frames.
  • Gate P · Oct 30 Simulated experiments match analytic answers within 0.5%; noisy virtual trials recover g inside the stated uncertainty.
  • Gate M · Oct 31 Real free-fall clip gives g within 3%. If not, Mode A is cut, and the pitch becomes virtual lab plus Mystery-g.
  • Gate D · Nov 2 A fresh account completes the whole flow on the deployed URL in under 5 minutes.

Honest read

The expected score is about the same as Measured's. What changes is the spread: the ceiling is clearly higher, because "upload my room and get a physics lab" is the kind of demo that wins a top-5 slot and the viral prize. The floor is lower, because there are more parts that can fail.

The plan protects the floor with the gates: if the 3D rebuild fails, the product degrades to a stylised world, not to nothing.

Biggest risks

  • Anti-project label: physics Q&A and reports can read as an "AI for Education chatbot". Lead with measurement and Real2Sim; the chat is a feature, not the product.
  • Circularity: solved only if every number is labelled measured or simulated.
  • Prior art: PhET, Algodoo and Labster are virtual labs, but none builds the lab from your own video or fits reality.
